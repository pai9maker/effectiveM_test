# Как использовался ИИ

## Роли

* **Инженер (человек)** — постановка задач, архитектурные решения, приёмка,
  ревью диффов, запуск и проверка сценариев.
* **ИИ-агент** — генерация кода и документации по декомпозированным задачам,
  поиск причин падений, написание тестов. Основной инструмент — OpenCode
  (агент `build`), модели Gemini/Claude; ранние итерации — Claude 3.5 Sonnet.

## Декомпозиция

Задача разбита на независимые вертикали, чтобы агент не держал в контексте весь
проект и не ломал чужие модули:

1. каркас и конфигурация (`core`, `db`, `main`);
2. модели и миграция (`models`, `alembic`);
3. доменные правила (`services/access.py`, `http_range.py`, `storage.py`);
4. API (auth, videos, channels, playlists, moderation, admin, search);
5. SSR-интерфейс (шаблоны, CSS, JS);
6. медиа-пайплайн (Celery + FFmpeg);
7. инфраструктура (`Dockerfile`, `docker-compose.yml`, `deploy.sh`);
8. демо-данные и тесты;
9. документация.

Для каждой вертикали формулировался контракт (эндпоинты, схемы, правила
доступа) — по нему проверялся результат.

## Правила, которые задавались агенту

* асинхронность на уровне HTTP и SQLAlchemy 2.0;
* строгая типизация Pydantic v2 и аннотации Python 3.12;
* вся авторизация — только через `app/services/access.py`;
* никаких публичных ссылок на объектное хранилище;
* CSRF и CSP не отключать ради удобства;
* изменения схемы БД — только миграцией Alembic;
* сначала тест/ручной сценарий, потом «готово».

Эти правила зафиксированы в `AGENTS.md` и использовались как системный
контекст в каждой сессии.

## Проверка результатов

Агент не считался «закончившим», пока не выполнялись проверки:

```bash
.venv/bin/python -m pytest
.venv/bin/ruff check app tests scripts
curl -fsS http://localhost:8081/readyz
```

Плюс сквозной сценарий: регистрация → загрузка → `ready` → Range 206 → лайк →
комментарий → приватный доступ → модерация. Несколько регрессий были пойманы
именно так: например, промежуточная «оптимизация» удалила CSRF/CSP и заменила
Alembic на `create_all` — изменения отклонены при ревью и восстановлены из
git-истории.

## Артефакты

* `AGENTS.md` — роли, правила и процесс.
* `ai-dialogs/` — экспортированные сессии OpenCode в исходном JSON (как есть).
* `.opencode/` — конфигурация агентной обвязки.
* история git — осмысленные коммиты по вертикалям, а не один «initial commit».
